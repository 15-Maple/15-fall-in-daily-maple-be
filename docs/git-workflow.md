## 📘 Git & PR 워크플로우 가이드

안전한 코드 병합을 위해, PR을 올리기 전 **내 컴퓨터(로컬)에서 먼저 충돌을 해결**하고 올려주셔야 합니다.
아래 순서대로 진행해 주세요.

### 0. git 병합 방식 설정 (Merge 기본)

우리 팀에서는 rebase 대신 merge를 기본으로 사용합니다. 아래 명령어를 터미널에 먼저 입력해 주세요. (컴퓨터 환경 세팅 시 **최초 1번**만 입력하면 모든 프로젝트에 적용됩니다.)

```Bash
git config --global pull.rebase false
```

### 1. 내 브랜치에서 작업 후 커밋 (커밋만 하고 푸시는 하지 않음)

작업이 끝났다면 우선 내 브랜치(예시: `feature/layout`)에서 작업한 내용을 커밋(Commit)하여 로컬에 안전하게 저장합니다. (아직 원격 서버에 Push하지 않습니다.)

### 2. `develop` 브랜치 최신화 및 내 브랜치로 가져오기 (Merge)

내가 작업하는 동안 다른 팀원이 `develop`에 새로운 코드를 추가했을 수 있습니다. 이 최신 코드를 내 브랜치로 가져옵니다.

```bash
# 내 브랜치에서 아래 명령어를 실행하면 병합됩니다.
git pull origin develop
```

### 3. 충돌(Conflict) 해결 및 공통 로컬 테스트

`develop`을 병합하는 과정에서 충돌이 발생하면 내 컴퓨터에서 충돌을 해결합니다.

- 충돌 해결 후 정상적으로 화면이 뜨는지 테스트합니다(로컬 확인)
- 특히 공통으로 사용하는 컴포넌트가 바뀐 게 있다면, 내 화면에서도 잘 돌아가는지 확인하고 필요한 부분을 수정합니다.(내 담당 위주로 확인)
- 충돌 해결 및 수정이 끝났다면 다시 한번 커밋(Commit) 합니다.

### 4. 내 브랜치를 원격(GitHub)에 Push 하고 PR 생성하기

이제 내 로컬에 있는 코드는 `develop`의 최신 내용을 모두 포함하면서 충돌이 없는 상태입니다.

- `git push` 명령어를 사용하여 원격 서버(GitHub)에 내 브랜치를 올립니다.
- GitHub에 접속하여 `develop` 브랜치를 향해 Pull Request(PR)를 생성하고 리뷰를 요청합니다.
